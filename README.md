# ⏱️ Pocket Clock — how much time does the QB really have?

We invented **Clean Pocket Time (CPT)**: the number of seconds between the snap and the moment a pass rusher gets within 2 yards of the QB. It is computed directly from the tracking data of the 8,532 dropbacks of the 2021 NFL season (weeks 1-8). Plays where no rusher arrives are treated as "censored" (Kaplan-Meier) instead of being thrown away.

**Key results:**
- Over the first 3 seconds, the **Rams'** pockets stay clean for 2.95 s on average, compared with 2.69 s for the **Vikings**.
- At 2.5 s, **87%** of pockets hold against 4 rushers, but only **70%** against 6 or more.
- **Trey Hendrickson** reaches the QB on 24% of his rushes, the best rate in the NFL.

**Who it is for:**
- **Offensive coach**: see where the line breaks down and which blockers get beaten most often.
- **Defensive coach**: see which rusher gets to the QB most often.
- **Scout**: compare blockers and rushers on an objective measure.
- **Broadcaster**: show a live "pocket clock" on air.

## Quick start

You need Python ≥ 3.10 and NumPy ≥ 2 (the code uses `np.trapezoid`).

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python run_all.py              # full pipeline: load → CPT → validation → figures
.venv/bin/streamlit run app.py           # interactive dashboard
.venv/bin/python -m src.export_html      # standalone HTML dashboard → outputs/pocket_clock_dashboard.html
```

| Command | What it does | Time |
|---|---|---|
| `python run_all.py` | Computes everything and writes `cache/` and `outputs/` | ~3 min the first time, then a few seconds (parquet cache) |
| `DEBUG=1 python run_all.py` | Same thing on 5 games only, for testing | a few seconds |
| `streamlit run app.py` | Dashboard: team view, league, players, play replay, method | requires one run of `run_all.py` |
| `python -m src.export_html` | Serverless HTML export (ranking, curves, 3 replays) | requires `cache/cpt_table.parquet` |
| `python -m src.load` / `python -m src.metrics` | Runs a single step and prints its summary | — |

The notebook [notebooks/analysis.ipynb](notebooks/analysis.ipynb) walks through the whole analysis (Restart & Run All works with the venv kernel). It is generated by [make_notebook.py](make_notebook.py), which needs `nbformat` (not listed in `requirements.txt`).

## Data

The project uses the Big Data Bowl 2023 data (**2021** season, weeks 1-8, 122 games). Put it in `data/`:

```
data/
├── games.csv  plays.csv  players.csv  pffScoutingData.csv
└── tracking/tracking_<gameId>.csv     # one file per game, 10 frames/s
```

The raw data is not versioned (~830 MB). See [README_original_dataset.md](README_original_dataset.md).

## Method in brief

- **CPT** = (first frame where the QB-rusher distance drops below 2 yd − snap frame) / 10. If no rusher arrives, CPT = observed duration and `censored = True`.
- Teams are ranked by **RMST**, the mean clean-pocket time over 3 s, i.e. the area under the Kaplan-Meier curve.
- **Expected CPT** comes from a Cox regression on game context. Actual − expected gives the line's added value, independent of the scheme.
- **Validation**: sacks have the shortest pockets (2.63 s vs 2.86 s on completions). Agreement with PFF pressures is φ = 0.61.

Details are in [docs/methodology.md](docs/methodology.md).

## Limitations

- **Small sample**: 8 weeks, about 250 plays per team. Gaps between teams (≤ 0.26 s) are trends, not certainties.
- **Arbitrary threshold**: the 2 yd radius is a choice. Rankings are only moderately stable to it (Spearman 0.73 between 1.5 and 2 yd, 0.45 between 2 and 3 yd).
- **Heavy censoring**: 68% of plays are censored, and the censoring is informative (a quick QB "hides" his line). Curves are unreliable beyond ~3 s.
- **What distance misses**: block quality, the QB's read and "mental" pressure. Tracking also stops at the throw.
